Construindo os dashboards no Metabase

Guia prático para conectar o PostgreSQL, criar perguntas SQL reutilizáveis, montar dashboards e entregar uma análise confiável de faturamento e recebíveis.

Pré-requisitos

  • Tabela DH_INVOICES criada e populada pelo Airflow
  • Metabase instalado e acessível (local, Docker ou cloud)
  • Usuário PostgreSQL com permissão de leitura no schema do DW
  • Rede liberada entre Metabase e 192.168.0.100:5432
  • Conhecimento básico de SQL e dos campos dl_*
i

Antes de abrir o Metabase, valide a carga no PostgreSQL:

SELECT COUNT(*), MAX(processed_at) FROM DH_INVOICES;

Se a tabela estiver vazia, execute as DAGs acctech_dl1 e acctech_dl2.

!

Valores de referência dos CSVs atuais: 12 faturas, 2 clientes, faturamento de R$ 535.122,94, recebido de R$ 409.603,52, saldo em aberto de R$ 125.519,42 e ticket médio de R$ 44.593,58. Use esses números para validar os primeiros cards.

Conectar o PostgreSQL

Acesse o painel administrativo

No Metabase, clique no ícone de engrenagem → Admin settings → Databases.

Adicione uma nova base

Clique em Add a database e escolha PostgreSQL.

Preencha a conexão

Display name: CRM DW
Host: 192.168.0.100
Port: 5432
Database name: nome do banco do Data Warehouse
Username: usuário de leitura
Password: senha do usuário

Configure SSL e salve

Habilite SSL se o servidor exigir. Clique em Save e depois em Sync database schema now. O Metabase deve listar a tabela DH_INVOICES (ou dh_invoices).

SQL · teste de conectividade
SELECT COUNT(*) AS total_faturas,
       MIN(dl_dt_date_facture) AS primeira_data,
       MAX(dl_dt_date_facture) AS ultima_data
FROM DH_INVOICES;
!

Use um usuário dedicado e somente leitura. Não utilize o mesmo usuário do Airflow no Metabase. Se o nome da tabela foi criado sem aspas, prefira DH_INVOICES sem aspas para evitar problemas de case sensitivity.

Organização da coleção

Crie uma coleção chamada Server | CRM Analytics e organize as perguntas em subcoleções. Isso facilita permissões, manutenção e reutilização.

Estrutura sugerida
Server | CRM Analytics/
├── 01_Visão Executiva/
├── 02_Faturamento/
├── 03_Recebíveis/
├── 04_Clientes/
└── 99_Temporário/        # rascunhos e validações

Nomeie as perguntas com um padrão claro: KPI — Faturamento total, Série — Faturamento mensal, Tabela — Faturas em aberto.

Perguntas SQL

No Metabase, use + New → SQL query, selecione o banco CRM DW e cole a consulta. Depois escolha a visualização e salve na coleção correspondente.

As consultas abaixo usam Field Filters opcionais: {{data_fatura}} mapeado para dl_dt_date_facture e {{cliente}} mapeado para dl_st_customer. Ao criar a pergunta, o Metabase exibirá os campos para configurar o tipo e o campo de cada variável.

i

Se preferir começar simples, remova os blocos [[AND {{...}}]] e crie os cards sem filtros. Adicione os filtros depois, na etapa de dashboard.

KPIs executivos

1. Faturamento total

SQL · PostgreSQL
SELECT COALESCE(SUM(dl_dc_total), 0) AS faturamento_total
FROM DH_INVOICES
WHERE 1 = 1
[[AND {{data_fatura}}]]
[[AND {{cliente}}]];

Visualização: número (Scalar). Formato: moeda BRL.

2. Recebido

SQL · PostgreSQL
SELECT COALESCE(
         SUM(dl_dc_total - COALESCE(dl_dc_balance, 0)),
         0
       ) AS recebido
FROM DH_INVOICES
WHERE 1 = 1
[[AND {{data_fatura}}]]
[[AND {{cliente}}]];

Visualização: número. Formato: moeda BRL.

3. Saldo a receber

SQL · PostgreSQL
SELECT COALESCE(SUM(dl_dc_balance), 0) AS saldo_a_receber
FROM DH_INVOICES
WHERE COALESCE(dl_dc_balance, 0) > 0
[[AND {{data_fatura}}]]
[[AND {{cliente}}]];

Visualização: número. Formato: moeda BRL.

4. Ticket médio

SQL · PostgreSQL
SELECT COALESCE(AVG(dl_dc_total), 0) AS ticket_medio
FROM DH_INVOICES
WHERE dl_dc_total IS NOT NULL
[[AND {{data_fatura}}]]
[[AND {{cliente}}]];

Visualização: número. Formato: moeda BRL.

5. Quantidade de faturas e clientes

SQL · PostgreSQL
SELECT
  COUNT(*) AS faturas,
  COUNT(DISTINCT dl_st_customer) AS clientes
FROM DH_INVOICES
WHERE 1 = 1
[[AND {{data_fatura}}]]
[[AND {{cliente}}]];

Visualização: dois números separados ou tabela de uma linha.

6. Taxa de recebimento

SQL · PostgreSQL
SELECT
  CASE
    WHEN SUM(dl_dc_total) = 0 THEN 0
    ELSE SUM(dl_dc_total - COALESCE(dl_dc_balance, 0))
         / SUM(dl_dc_total)
  END AS taxa_recebimento
FROM DH_INVOICES
WHERE COALESCE(dl_dc_total, 0) > 0
[[AND {{data_fatura}}]]
[[AND {{cliente}}]];

Visualização: número. Formato: percentual (0 a 100%).

Faturamento

Série mensal de faturamento

SQL · PostgreSQL
SELECT
  DATE_TRUNC('month', dl_dt_date_facture) AS mes,
  SUM(dl_dc_total) AS faturamento,
  COUNT(*) AS faturas
FROM DH_INVOICES
WHERE dl_dt_date_facture IS NOT NULL
[[AND {{data_fatura}}]]
[[AND {{cliente}}]]
GROUP BY 1
ORDER BY 1;

Visualização: linha ou barras. Eixo X: mês. Y: faturamento.

Faturamento por cliente

SQL · PostgreSQL
SELECT
  dl_st_customer AS cliente,
  SUM(dl_dc_total) AS faturamento,
  COUNT(*) AS faturas,
  AVG(dl_dc_total) AS ticket_medio
FROM DH_INVOICES
WHERE dl_st_customer IS NOT NULL
[[AND {{data_fatura}}]]
GROUP BY 1
ORDER BY 2 DESC
LIMIT 10;

Visualização: barras horizontais ordenadas por faturamento.

Distribuição por moeda

SQL · PostgreSQL
SELECT
  COALESCE(dl_st_currency, 'N/D') AS moeda,
  COUNT(*) AS faturas,
  SUM(dl_dc_total) AS faturamento
FROM DH_INVOICES
GROUP BY 1
ORDER BY 3 DESC;

Visualização: pizza ou barras. Use tabela se houver mais de 4 moedas.

Tabela de faturas detalhadas

SQL · PostgreSQL
SELECT
  dl_st_ref              AS referencia,
  dl_st_customer         AS cliente,
  dl_dt_date_facture     AS emissao,
  dl_dt_due_to           AS vencimento,
  dl_dc_total            AS total,
  COALESCE(dl_dc_balance, 0) AS saldo,
  dl_st_currency         AS moeda
FROM DH_INVOICES
WHERE 1 = 1
[[AND {{data_fatura}}]]
[[AND {{cliente}}]]
ORDER BY dl_dt_date_facture DESC;

Visualização: tabela, com formatação de moeda nas colunas total e saldo.

Recebíveis e aging

Faturas em aberto

SQL · PostgreSQL
SELECT
  dl_st_ref                         AS referencia,
  dl_st_customer                    AS cliente,
  dl_dt_due_to                      AS vencimento,
  dl_dc_total                       AS total,
  dl_dc_balance                     AS saldo,
  (CURRENT_DATE - dl_dt_due_to::date) AS dias_atraso
FROM DH_INVOICES
WHERE COALESCE(dl_dc_balance, 0) > 0
[[AND {{cliente}}]]
ORDER BY dl_dt_due_to ASC;

Visualização: tabela. Destaque valores positivos em dias_atraso.

Total vencido e a vencer

SQL · PostgreSQL
SELECT
  COALESCE(SUM(CASE
    WHEN dl_dt_due_to::date < CURRENT_DATE THEN dl_dc_balance
    ELSE 0
  END), 0) AS vencido,
  COALESCE(SUM(CASE
    WHEN dl_dt_due_to::date >= CURRENT_DATE THEN dl_dc_balance
    ELSE 0
  END), 0) AS a_vencer
FROM DH_INVOICES
WHERE COALESCE(dl_dc_balance, 0) > 0
[[AND {{cliente}}]];

Visualização: dois números ou barras comparativas.

Aging por faixa de atraso

SQL · PostgreSQL
SELECT
  CASE
    WHEN dl_dt_due_to IS NULL THEN 'Sem vencimento'
    WHEN dl_dt_due_to::date >= CURRENT_DATE THEN 'A vencer'
    WHEN CURRENT_DATE - dl_dt_due_to::date <= 30 THEN '1-30 dias'
    WHEN CURRENT_DATE - dl_dt_due_to::date <= 60 THEN '31-60 dias'
    WHEN CURRENT_DATE - dl_dt_due_to::date <= 90 THEN '61-90 dias'
    ELSE '90+ dias'
  END AS faixa,
  COUNT(*) AS faturas,
  SUM(dl_dc_balance) AS saldo
FROM DH_INVOICES
WHERE COALESCE(dl_dc_balance, 0) > 0
[[AND {{cliente}}]]
GROUP BY 1
ORDER BY 1;

Visualização: barras ordenadas por faixa. Cores: verde (a vencer), amarelo (1-30), laranja (31-90), vermelho (90+).

Clientes

✓

Nos CSVs atuais, faturas e cadastro usam o mesmo nome (AirFrance e TAP). As 12/12 faturas encontram cliente no merge, portanto dl_st_customer_code e dl_st_document estão preenchidos. O ranking mostra AirFrance com 4 faturas e R$ 455.308,37.

Ranking e participação na receita

SQL · PostgreSQL
SELECT
  dl_st_customer AS cliente,
  SUM(dl_dc_total) AS faturamento,
  ROUND(
    100.0 * SUM(dl_dc_total)
    / NULLIF(SUM(SUM(dl_dc_total)) OVER (), 0),
    2
  ) AS participacao_pct,
  COUNT(*) AS faturas,
  AVG(dl_dc_total) AS ticket_medio
FROM DH_INVOICES
WHERE dl_st_customer IS NOT NULL
[[AND {{data_fatura}}]]
GROUP BY 1
ORDER BY 2 DESC;

Visualização: tabela com barras na coluna de faturamento ou gráfico de barras.

Histórico mensal por cliente

SQL · PostgreSQL
SELECT
  DATE_TRUNC('month', dl_dt_date_facture) AS mes,
  dl_st_customer AS cliente,
  SUM(dl_dc_total) AS faturamento
FROM DH_INVOICES
WHERE dl_dt_date_facture IS NOT NULL
  AND dl_st_customer IS NOT NULL
[[AND {{cliente}}]]
GROUP BY 1, 2
ORDER BY 1, 2;

Visualização: linha com uma série por cliente (limite a poucos clientes para manter a legibilidade).

Clientes com saldo em aberto

SQL · PostgreSQL
SELECT
  dl_st_customer AS cliente,
  COUNT(*) AS faturas_abertas,
  SUM(dl_dc_balance) AS saldo_aberto,
  MIN(dl_dt_due_to) AS vencimento_mais_antigo
FROM DH_INVOICES
WHERE COALESCE(dl_dc_balance, 0) > 0
GROUP BY 1
ORDER BY 3 DESC;

Visualização: tabela ou barras horizontais.

Montagem dos dashboards

Crie cada dashboard em + New → Dashboard. Adicione os cards salvos, organize o layout em uma grade e conecte os filtros.

01

Visão Executiva

  • Linha de KPIs: faturamento, recebido, saldo, ticket médio, faturas.
  • Série mensal de faturamento.
  • Recebido x em aberto (pizza/rosca).
  • Tabela de faturas em aberto.
02

Faturamento

  • Faturamento mensal e quantidade de faturas.
  • Top 10 clientes.
  • Distribuição por moeda.
  • Tabela detalhada de faturas.
03

Recebíveis e Aging

  • KPIs vencido e a vencer.
  • Aging por faixa de atraso.
  • Clientes com saldo em aberto.
  • Tabela de faturas em aberto ordenada por vencimento.
04

Clientes

  • Ranking com participação na receita.
  • Ticket médio por cliente.
  • Histórico mensal por cliente.
  • Clientes com saldo em aberto.

Ordem recomendada

  1. Salve todos os cards antes de montar o dashboard.
  2. Adicione primeiro os KPIs no topo, em uma única linha.
  3. Coloque os gráficos de tendência no centro.
  4. Deixe as tabelas detalhadas na parte inferior.
  5. Ative Auto-arrange e revise o layout em desktop e mobile.
  6. Adicione um texto explicativo com a data da última carga.
SQL · último processamento (card de contexto)
SELECT MAX(processed_at) AS ultima_carga
FROM DH_INVOICES;

Filtros e variáveis

Adicionar filtros ao dashboard

  1. No dashboard, clique em Add filter.
  2. Escolha Time → Date range e nomeie como “Data da fatura”.
  3. Em cada card, abra o menu → Connect to a filter.
  4. Para cards SQL, mapeie o filtro para a variável data_fatura.
  5. Repita com um filtro de categoria para cliente.

Configurar as variáveis SQL

  • data_fatura: tipo Field Filter, campo DH_INVOICES.dl_dt_date_facture.
  • cliente: tipo Field Filter, campo DH_INVOICES.dl_st_customer.
  • Se usar variáveis simples, defina data_inicio e data_fim como Date.
i

Os blocos [[AND {{...}}]] são opcionais: se o filtro não for preenchido, a consulta ignora a condição. Isso permite reutilizar o mesmo card em contextos com e sem filtro.

Formatação e legibilidade

  • Moeda: configure BRL nas colunas e KPIs monetários.
  • Percentual: use 0 a 100% com uma casa decimal.
  • Datas: formato dd/MM/yyyy para o público brasileiro.
  • Números grandes: exiba “R$ 535,1 mil” em KPIs e valores completos nas tabelas.
  • Cores: verde para recebido, amarelo para a vencer, vermelho para vencido.
  • Tabelas: alinhe valores à direita e defina largura mínima para nomes de clientes.
  • Títulos: use perguntas de negócio, não nomes técnicos de colunas.

Alertas, assinaturas e permissões

Alertas

  • Crie um alerta para “Saldo a receber acima de X” ou “Fatura vencida há mais de 30 dias”.
  • Configure a frequência diária e os destinatários.
  • Use o card de faturas em aberto como base para o alerta.

Assinaturas

  • Agende o envio do dashboard executivo semanal para a diretoria.
  • Envie o dashboard de recebíveis diariamente para o financeiro.
  • Inclua um texto com a data da última carga no dashboard.

Permissões

  • Crie grupos: Diretoria, Financeiro, Operação.
  • Conceda acesso somente às coleções e dashboards necessários.
  • Mantenha a coleção 99_Temporário restrita à equipe de dados.
  • Use a conta de serviço do Metabase apenas para a conexão com o DW.

Boas práticas

  • Uma pergunta, uma responsabilidade: evite SQL gigante em um único card.
  • Reutilize cards: o mesmo KPI pode aparecer em vários dashboards.
  • Documente as regras: descreva o cálculo na descrição do card.
  • Valide contra a origem: compare totais do Metabase com consultas no PostgreSQL.
  • Cuidado com COALESCE: saldo nulo do Dolibarr é tratado como zero; isso afeta a leitura de recebíveis.
  • Performance: use filtros de data e evite SELECT * em tabelas grandes.
  • Versionamento: mantenha o SQL dos cards também na documentação do repositório.
!

Como a tabela é recarregada diariamente, dashboards podem refletir a carga mais recente. Se precisar de histórico, evolua o modelo para uma tabela de fatos com snapshots ou um modelo dbt com dimensões de tempo.

Checklist final

  • Conexão PostgreSQL testada e schema sincronizado
  • Cards de KPI salvos na coleção correta
  • Séries temporais com datas e valores formatados
  • Dashboard executivo montado e responsivo
  • Filtros de data e cliente conectados aos cards
  • Cards de recebíveis com COALESCE aplicado
  • Permissões e grupos configurados
  • Alertas e assinaturas ativos
  • Consultas validadas contra o PostgreSQL
  • Documentação do dashboard atualizada no repositório
